# 现状章节结构与小节命名规则

## 通用原则
1. **小节标题动词要具体**：避免"相关情况""基本情况"等空标题。
2. **同级小节结构对称**：3.2 下的 4 个子节都用"流程"或都用"环节"做名词。
3. **小节数量控制在 3-5 个**：过少（≤2）显得单薄，过多（≥6）失焦。
4. **先事实后小结**：每节用事实陈述，最后一段才给"问题引出"。
5. **章节末尾的过渡句**：1 句即可，自然衔接到"问题分析"或"优化策略"。

## 命名规范

### 公司概况子节（3.1.x）
| 子节 | 标准命名 | 必备内容 |
|------|----------|----------|
| 3.1.1 | 企业基本情况 | 成立时间、规模、行业地位、战略定位 |
| 3.1.2 | 组织架构 | 集团-子公司-职能中心三级描述 |
| 3.1.3 | 业务范围 | 按业务板块拆分，含客户/供应商 |

### 流程现状子节（3.2.x）
按业务核心 4 流程拆：
- 3.2.1 计划/规划
- 3.2.2 执行/作业
- 3.2.3 质量/检验/控制
- 3.2.4 物料/资源/物流

若业务流程不足 4 个，可压缩到 3 个；超过 5 个则要合并。

### 数字化现状子节（3.3.x）
按"基础-应用-管理"三层拆：
- 3.3.1 基础建设（网络、平台、数据治理）
- 3.3.2 生产端/业务端建设
- 3.3.3 管理端/决策端建设

## 行业 / 政策型（3.x）
- 3.1 行业概况
- 3.2 市场规模与结构
- 3.3 竞争格局
- 3.4 政策环境
- 3.5 典型案例（可选）

## 技术 / 系统型（3.x）
- 3.1 概念界定
- 3.2 国内外研究现状（轻综述，区别于第二章）
- 3.3 主流技术路线对比
- 3.4 典型应用场景
- 3.5 现有方案的不足

## 章节开头与结尾的固定模式

### 章节开头（推荐模板）
> "B公司[主题]管理活动围绕[核心目标]展开，从[起点]到[终点]的全链路均已建立相应的管理流程。基于[来源]，可将现行[主题]管理体系拆解为[子主题1]、[子主题2]和[子主题3][数字]条核心流程。"

### 章节末尾过渡句（推荐模板）
> "从总体看，B公司[主题]在[已具备的基础]方面已具备[程度]水平，但在[存在不足]方面仍[存在的现实问题]，这也是后续章节讨论其[下一步]优化策略的现实基础。"

## 避免的标题类型
- "其他方面" / "其他问题" - 失焦
- "公司发展历程" - 容易写成公司简介，不算现状
- "现状综述" - 与章节名重复
- "X 方面现状研究" - "研究"是论文整体动词，子标题不要再用
